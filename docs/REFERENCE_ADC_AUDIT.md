# 经典仓库对照、Truck故障与稳定性修改

本次审计日期：2026-10-21。参考源码副本及SHA-256保存在
`reference_audit/manifest.json`，副本仅供对照，不作为运行模块导入。

## 参考了哪些通用机制

| 官方源码 | 通用机制 | 本项目处理 |
|---|---|---|
| [原始3DGS](https://github.com/graphdeco-inria/gaussian-splatting/blob/main/scene/gaussian_model.py)，`add_densification_stats` | 可见点投影XY梯度范数，按观测次数归一化 | 已采用；不保留世界坐标梯度分支 |
| 同上，`densify_and_clone/split` | 小点克隆；大点分裂为两个子点；子尺度除以0.8×2；移除大父点 | 新增尺度感知增密，保留Smol-GS的独立点和MLP |
| 同上，`densify_and_prune` | 在启用尺寸筛选时按屏幕尺寸及0.1×scene_extent剪枝 | 采用固定场景尺度的世界尺度筛选；未搬入屏幕半径剪枝或opacity reset |
| 同上，`cat_tensors_to_optimizer` | 保留点Adam状态迁移，新点状态清零 | 原有实现已符合，新测试覆盖分裂后新尺度和优化器对应关系 |
| [HAC](https://github.com/YihangChen-ee/HAC/blob/main/scene/gaussian_model.py)，`training_statis/anchor_growing` | XY梯度统计、有效观测计数、多级网格增长、新anchor按网格大小重设尺度 | 核对统计及新增点尺度生命周期；未引入anchor/offset |
| [Scaffold-GS](https://github.com/city-super/Scaffold-GS/blob/main/scene/gaussian_model.py)，`anchor_growing` | 网格内去重、新anchor按当前网格大小初始化尺度 | 作为“新增点不能无限继承大尺度”的对照，未搬入模型层级 |
| [HAC train.py](https://github.com/YihangChen-ee/HAC/blob/main/train.py) | `0.01*scaling.prod(dim=1).mean()`尺度体积正则 | Smol-GS论文目标中没有此项，暂不加入 |

HAC的`_prune_anchor_optimizer`还会将后3个**对数尺度参数**上限设为0.05；
它不是物理尺度0.05，也不应原样套到Smol-GS的3维控制器。
指数/对数尺度参数化在这些经典仓库里很常见，`exp(log_s)`本身并不构成bug。
需要结合新点尺度设置、分裂和剪枝来控制尺度生命周期。

## 原运行发生了什么

数据来自`outputs/truck_screen_base_20261021/geometry_growth_diagnosis.json`、
`extreme_parent_probe.json`及保存的检查点，不是新训练结果。

| 时刻 | 点数 | X轴跨度 | 最大控制器尺度 |
|---|---:|---:|---:|
| SfM初始化 | 136,029 | 325.66 | 59.38 |
| 7k | 698,775 | 4,405.62 | 12,411.39 |
| 15k | 888,708 | 50,751.44 | 22,055.56 |
| 30k，量化前 | 571,630 | 50,751.44 | 77,488.88 |

原实现把所有高梯度点都作为同一种随机克隆处理：按父点当前预测协方差采样，
子点完整继承父点缩放控制器，父点同时保留。没有大点分裂缩尺度，也没有世界尺度剪枝。
这允许大点重复生成远处大点。对保存的远处点做8视角属性检查，实际预测尺度也达到
控制器的巨大数量级；它们不只是看起来很大的未激活控制器参数。

为什么原剪枝没清掉它们：巨大投影足迹仍可覆盖图像，`radii>0`便计为可见；
远处点的opacity中位数仍高于0.005（20k约0.013，30k约0.037），最近也有可见记录。
因此“低opacity或持续不可见”不足以清掉它们。没有证据支持“opacity普遍饱和为1”的解释。

坐标压缩时按全体点min/max划分R=16网格，X单元宽度达到0.7744。
514,172/571,630个点落入重复叶并被删除（89.95%），PSNR从30k的22.976降至35k的15.940。
这是已确认的最后一段故障链。保存数据没有父子ID历史，不能声称已经逐点还原全部祖先关系；
早期尺度为何开始增大、修复后的完整指标仍需新实验验证。

## 本次实现的选择与边界

1. 固定参考尺度来自**训练相机**中心的1.1倍最大离心半径，不用会被异常点撑大的点云包围盒。
   Truck训练相机半径约5.8479；旧诊断采用的相机集合略有差异，半径约5.8434。
2. 小点同坐标克隆，大点分裂为两个、s除以1.6并移除父点；新点Adam动量清零。
   阈值采用3DGS的0.01×scene_extent；可选点数限制按净增加点数计算。
3. 从3000步起，在ADC周期按0.1×scene_extent筛除超大控制器点，并检查几何有限性。
   这里用Smol-GS的控制器作为跨视角最终轴尺度上界，比检查某一相机的预测尺度更严格。
   为防止为已知异常点继续采样，尺寸筛选在产生新点之前执行。
4. 坐标冻结前先计算真实碰撞率；超过50%时终止并保留模型、bounds和Adam状态。
   阈值是可配置的故障检查，不能视为质量保证。没有通过增大R或分位数裁边来隐藏异常。
5. 每个训练日志行增加包围盒、控制器最大值；ADC日志另记clone、split和异常剪枝数。
   配置/元数据记录新策略；旧检查点可渲染、诊断，但不能静默续跑。

**与论文的差异必须保留：**Smol-GS正文描述随机克隆并继承f，没有明确规定上述尺度分裂、
阈值、尺寸剪枝。小点同坐标克隆也不同于其正文的随机坐标描述。本修改是参考经典实现的
稳定性工程基线，不是恢复了未公开的作者源码。未改动单点f/s、MLP、损失系数、二维梯度阈值、
R=16或五阶段时长，未加入HAC体积正则及anchor结构。

## 验证与后续实验

回归测试包括CPU/CUDA真实渲染梯度、大小点分流、子尺度收缩、Adam状态、净点数预算、
可见且有opacity的超大点剪枝，以及碰撞失败时模型和优化器不变。
16项测试通过，日志：`outputs/validation/reference_adc/tests.log`。
启动脚本通过bash语法检查，Truck单场景队列通过dry-run检查；这些检查没有启动正式训练。

对原30k检查点的只读核验：
`outputs/validation/reference_adc/truck_30000_guard.json`。检查会拦住原来的89.95%删除，
原检查点文件未更改。该报告中的尺度筛选仅是几何反事实检查，没有训练或图像质量评测，
不能把筛选后的点数当成复现结果。

只读筛选中，超大控制器点为22,392个，占3.92%；去掉这些点后X轴跨度从50,751降到144.67，
R=16碰撞率降为0.5919%（549,238点对应545,987个不同叶）。这支持少量异常点支配
全局网格精度的判断，但不说明删除这些点后的图像质量，也不是从头训练结果。
